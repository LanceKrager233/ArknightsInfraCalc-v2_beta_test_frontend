# 一图流辅助设施与宿舍紧凑重排设计

## 目标

- 仅调整一图流中的会客室、办公室和房间编排容器。
- 两张卡片复用发电站的横排结构，实际内容高度约为 110px，并保持彼此等高。
- 控制中枢维持现有布局和高度。
- 右侧宿舍整体上移，宿舍 1 紧接会客室/办公室下方，消除紧凑卡片留下的空白。
- 列表式布局、排班数据、效率、API、`own:false` 和加工站规则保持不变。

## 布局

- 一图流外层从共享行高的两列网格改为 `55% / 45%` 的两列独立垂直堆叠。
- 左列顺序保持为控制中枢、贸易/制造工作站、发电站。
- 右列顺序为会客室/办公室、宿舍 1、宿舍 2、宿舍 3、宿舍 4。
- 两列内部和列间继续使用 12px 间距；左右列不会再互相共享行高。
- 会客室和办公室继续使用现有 `65% / 35%` 宽度。
- 卡片左侧显示房间标题与等级，右侧显示干员头像和头像下方的名字。
- 会客室保留两个槽位，办公室保留一个槽位；头像尺寸继续使用一图流的 `clamp(64px, 5.9vw, 76px)`。
- 多个头像继续保持 8px 间距。
- 右上辅助设施容器顶部对齐，避免两张卡片互相拉伸。

## 实现边界

- 在一图流展示策略中定义可复用的横排房间判断，覆盖 `power`、`meeting` 和 `hire`。
- `CompactRoomCard` 复用现有发电站横排卡片与干员区域样式；发电站效率展示保持原逻辑。
- `CompactScheduleView` 仅重排渲染容器，不改变分组数据、房间排序或卡片内容。
- 不修改共享 `OperatorSlot`、列表式组件、数据类型或公共 API。

## 验证

- 先增加失败测试，覆盖会客室、办公室和发电站使用横排策略，其他房间保持纵排。
- 运行 `npm test`、`npm run lint`、`npm run build`。
- 使用 Full E2 在 1280px 侧栏展开/收缩及 1920px 下验收：
  - 会客室和办公室高度彼此相等，目标约 110px。
  - 标题保持距卡片左侧 24px、顶部 12px。
  - 头像和名字不裁切，头像间距保持 8px。
  - 宿舍 1 距会客室/办公室底部 12px，宿舍 2–4 依次保持 12px 间距。
  - 控制中枢和左列房间布局不变，页面无横向溢出。
  - 列表式功能设施仍为 3+2，加工站仍默认折叠。

## 交付

- 从功能分支创建面向上游 `main` 的非 Draft PR。
- 完成合并前 Review，通过后使用普通 merge。
- 拉取合并后的 `main`，按合并 SHA 创建新 release 并发布。
- 保留 `.env.local`、`bin/data` 与 `/var/lib/arknights-infra`，发布后验证公网 4174、内部 4175、健康接口、Full E2、两种布局和服务日志。
