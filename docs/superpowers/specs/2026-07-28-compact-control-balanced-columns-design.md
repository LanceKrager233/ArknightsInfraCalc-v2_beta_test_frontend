# 一图流控制中枢压缩、双列等高与设施背景设计

## 目标

- 仅修改一图流布局，列表式布局保持现状。
- 将控制中枢改为与会客室、办公室相同的横排短卡片，高度约为 `110px`。
- 让一图流左右两列的可见卡片底边对齐，误差不超过 `1px`。
- 为一图流的每张房间卡片加入列表式现有的对应设施背景图标。
- 保留当前房间顺序、头像尺寸、头像间距、产品标签、排班结果和所有后端行为。

## 布局设计

### 控制中枢

- 控制中枢加入一图流横排卡片集合，与发电站、会客室和办公室复用同一短卡片高度规则。
- 左侧显示设施色条、标题和等级；右侧显示 5 个干员格。
- 为保证 1280px 且侧边栏展开时不与 5 个干员格重叠，控制中枢等级放在标题下方；设施色条仍从卡片左侧 `12px` 开始，标题仍从左侧 `24px` 开始。
- 干员格继续使用 `clamp(64px, 5.9vw, 76px)`，间距继续为 `8px`，名字仍在头像下方。
- 控制中枢、会客室和办公室的卡片高度误差不超过 `1px`。

### 左右列等高

- 外层一图流双列容器改为交叉轴拉伸，使左右列共享较高一列的高度。
- 左列仍按以下顺序排列：
  1. 控制中枢；
  2. 贸易站与制造站两两成行；
  3. 发电站行。
- 右列仍按以下顺序排列：
  1. 会客室与办公室 `65% / 35%`；
  2. 宿舍 1–4。
- 四个宿舍外层使用相同的 `flex-grow`，均匀吸收控制中枢压缩后的剩余高度。
- 四个宿舍保持彼此等高，卡片之间继续使用 `12px` 间距。
- 宿舍标题继续固定在卡片顶部；干员区域在标题以下的可用空间中垂直居中，避免新增空间只堆积在卡片底部。
- 标准 Full E2 243 布局下，左右两列可见卡片底边误差不超过 `1px`。
- 其他现有布局继续以“不裁切、不重叠、不横向溢出”为首要约束；不通过固定像素总高绑定布局。

## 设施背景图标

- 直接复用 `roomVisualFor(group).background`，不新增或复制图片资源。
- 一图流每张房间卡片增加与列表式一致的背景层：
  - 背景位置：`-18px center`；
  - 背景尺寸：`auto 176px`；
  - 不重复；
  - 透明度：`0.52`。
- 背景上方增加与列表式一致的从左到右深色渐变：
  - 左侧保留图标辨识度；
  - 中部降低文字干扰；
  - 右侧回到卡片底色，确保头像清晰。
- 标题、效率、产品标签和干员格均位于背景层上方，不改变点击、语义或排版行为。
- 加工站继续不在一图流中显示，因此不新增加工站一图流背景。

## 范围约束

- 不修改列表式布局组件和列表式几何策略。
- 不改变一图流的 `55% / 45%` 主列比例、会客室/办公室 `65% / 35%` 比例、房间顺序或加工站隐藏规则。
- 不修改排班数据、效率算法、API、森空岛流程、反馈 JSON、MAA JSON、`own:false` 行为或持久化目录。
- 不修改共享图片资源本身。

## 验证

### 自动化

- 扩展 `src/schedule-view-presentation.test.ts`，覆盖：
  - 控制中枢使用横排短卡片；
  - 双列容器使用拉伸策略；
  - 宿舍使用等比例增长策略；
  - 背景位置、尺寸、透明度和渐变策略；
  - 既有加工站隐藏与其他分组策略不回归。
- 运行：
  - `npm test`
  - `npm run lint`
  - `npm run build`
  - `git diff --check`

### 浏览器

- 使用 Full E2 243 数据在以下状态验收：
  - 1280px，侧边栏展开；
  - 1280px，侧边栏收缩；
  - 1920px。
- 验收标准：
  - 控制中枢、会客室和办公室高度差不超过 `1px`；
  - 控制中枢标题、等级和 5 个干员格无重叠；
  - 四个宿舍彼此等高，间距均为 `12px`；
  - 左右列底边误差不超过 `1px`；
  - 所有一图流房间显示正确设施背景，透明度和渐变符合设计；
  - 无头像、名字、标题或产品标签裁切；
  - 页面无横向溢出；
  - 列表式功能设施 3+2、88px 干员框和加工站默认折叠均保持不变。

## 已确认选择

- 列高处理采用方案 A：控制中枢压缩，四个宿舍均匀吸收剩余高度。
- 背景处理采用方案 A：完全复用列表式的背景资源、左侧位置、`52%` 透明度和同款渐变。
